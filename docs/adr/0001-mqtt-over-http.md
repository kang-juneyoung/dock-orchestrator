# 0001. 장비 통신에 HTTP 대신 MQTT를 쓴다

**상황** 트럭 컨트롤박스는 LTE로 붙는다. 사설 IP 뒤에 있어 서버가 먼저 연결할 수 없고, 신호가 자주 끊긴다.
서버에서 적재 명령을 즉시 내려야 하고, 장비는 초 단위로 상태를 올린다.

**결정** 장비가 브로커에 상시 연결하는 MQTT를 쓴다.
- 명령 `dock/<tenant>/<truck>/cmd` QoS 1 / 이벤트 `.../evt` QoS 1 / 상태 `.../status` QoS 0 retained
- 장비 세션은 `clean_session=False`라 잠시 끊겨도 브로커가 명령을 보관한다.
- LWT(유언 메시지)로 비정상 종료를 알리고, 서버는 하트비트 만료(5초)로도 두절을 판정한다.

**대안** HTTP 폴링은 명령 지연이 폴링 주기만큼 생기고 트래픽이 크다. WebSocket은 재연결·QoS를 직접 구현해야 한다.

**결과** 토픽에 tenant가 들어가 브로커 ACL로 고객사 분리가 가능하다. 대신 브로커가 운영 대상에 추가된다.
