# 0002. 통신이 끊겨도 장비 이벤트를 잃지 않는다

**상황** 적재 중 LTE가 끊기면 "몇 개 실었는지", "완료했는지"가 서버에 가지 않는다. 이 정보는 WMS 보고와 과금의 근거다.

**결정** 장비에 SQLite 아웃박스를 둔다.
1. 이벤트를 만들면 먼저 디스크에 기록하고 (전원 차단에도 보존)
2. 브로커의 수신 확인(PUBACK)을 받으면 삭제하고
3. 재연결되면 남은 이벤트를 seq 순서대로 다시 보낸다.

**결과** at-least-once 전달이 된다. 같은 이벤트가 두 번 갈 수 있으므로 서버는 evt_id로 중복을 걸러낸다 (0003).
장비 상태 메시지에 미전송 건수(`pending_events`)를 실어 관제 화면에 보여준다.

**검증** `tests/test_agent.py::test_events_survive_disconnect_and_flush_in_order`, README 시연 2~3.
