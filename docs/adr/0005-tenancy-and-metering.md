# 0005. 고객사 데이터 분리와 사용량 기반 과금의 근거

**상황** 관제 서비스를 여러 물류사에 구독형으로 제공하려면 데이터가 섞이지 않아야 하고, 청구 근거가 남아야 한다.

**결정**
- 모든 테이블·토픽·API 경로에 tenant를 둔다. 연동 API는 고객사별 API Key로 인증한다.
- 같은 도크 번호라도 tenant가 다르면 매칭하지 않는다.
- 작업 **완료** 이벤트 기준으로 월별 작업 건수·팔레트 수를 집계한다 (`GET /api/<tenant>/usage`).
  중복 이벤트는 0003에 의해 걸러지므로 이중 청구가 생기지 않는다.

**과금 모델 후보** 트럭(컨트롤박스)당 월 기본료 + 처리 팔레트 종량. 두 값 모두 이 집계에서 나온다.

**검증** `test_tenants_are_isolated`, `test_full_cycle`(사용량), `test_duplicate_event_is_ignored`.
